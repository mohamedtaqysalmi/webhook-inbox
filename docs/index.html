webhook-inbox

Receive webhooks into a private inbox, inspect bodies and headers, then replay them to a checked target.

View repository Open signature calculator

What problem it solves

Provider dashboards often hide the raw webhook. Local tunnels expire. webhook-inbox gives you a durable, searchable catcher you control, with signature helpers and guarded replay.

Quickstart

git clone https://github.com/mohamedtaqysalmi/webhook-inbox.git
cd webhook-inbox
docker compose up --build
# open http://localhost:8000 and create an endpoint

How it works

      
    
        
  1. Capture — any method on /h/{token} streams the body with a hard size limit into SQLite.
    2. 
        
  2. Inspect — JSON API or HTMX UI lists and filters requests; detail shows headers and body.
    3. 
        
  3. Replay — outbound call after SSRF validation; result logged with status and preview.
    4. 
        
  4. Housekeeping — retention deletes old rows; rate limit protects create/receive.

How I built it

      
    
        
  • stdlib SQLite over an ORM — two tables and a handful of queries; less dependency surface.
    • 
        
  • HTMX instead of React — server-rendered inbox with partials; see ADR 0001.
    • 
        
  • SSRF checks resolve DNS — block non-public addresses by default; private replay is opt-in for local demos.
    • 
        
  • Signature helpers stay a library — verification is available without forcing a single provider auth model on every endpoint.
    • 
      

    


    

      
Honest limitations

      
    
        
  • Endpoint tokens are the only access control; put auth in front for anything shared.
    • 
        
  • Rate limits are in-process memory; they do not coordinate across multiple workers.
    • 
        
  • SSRF validation does not yet pin the resolved IP on the socket (DNS rebinding residual risk).
    • 
        
  • Postgres is not wired yet; SQLite is the supported store.
